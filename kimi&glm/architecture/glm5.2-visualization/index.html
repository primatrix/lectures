Chapter 12 / Kimi Delta Attention

KDA：先遗忘，再纠正当前 key，最后写入

KDA 把固定状态当作可修改的关联记忆：先决定旧状态保留多少，再削弱当前 key 对应的旧映射，写入新的 key → value 关联，最后由 query 读取。

KDA state update · one attention head forget → correct → write → read
① FORGET · Diag(αt)St−1 先缩放旧状态的每个 key channel：α 接近 1 多保留，接近 0 多遗忘。
② CORRECT · I − βtktkt⊤ 压低状态沿当前 key 方向给出的旧响应，先移除会与新 value 冲突的部分。
③ WRITE · + βtktvt⊤ 把新的 key → value 关联写入状态；βt 同时控制修正与写入强度。
④ READ · ot = St⊤qt query 从更新后的状态中读取；等价式说明 KDA 只写入新目标与旧预测之间的差值。

Chapter 17 / LatentMoE

LatentMoE：把 Top‑16 专家路径压到半宽

K3 的 896 个 routed experts 中，每个 token 选择 16 个。专家池很稀疏，但 Top‑16 仍会同时放大专家计算与跨卡 payload；K3 只把 routed path 从 d=7168 压到 ℓ=3584。

896 routed experts · Top‑16 · routed width 7168 → 3584 scale width → compress routed path → quantify savings
896 experts · Top‑16 每个 token 只激活 1 / 56 的 routed expert pool
真正的系统问题：一个 token 同时走 16 条专家路径 Top‑k 越高，Expert GEMM、专家权重读取和 EP All‑to‑All payload 越大。
Router 仍读取完整的 7168 维输入，再选择 Top‑16 专家。 x[7168] → Router → Top‑16 indices + weights Router 直接读取 full-width x；W↓ 与 Router 是并行分支，不是先压缩再选路。

Chapter 26 / Fused MoE pipeline

一个 Fused Kernel，按 Expert Wave 排跨引擎流水

把 Scatter、Expert FFN、权重预取和 Gather 放进同一个调度域：当前 wave 在 MXU 上计算时，HBM DMA 预取下一组权重，ICI 与 VPU/VMEM 同时推进相邻 wave。

Inside one Pallas kernel · per-expert-wave schedule ICI · HBM DMA · MXU · VPU / VMEM
01 · ICI 提前启动 Scatter All-to-All 先把 routed tokens 发往对应 expert owner，后续 wave 持续进入通信。
02 · HBM DMA 双 Buffer 预取权重 Buffer A 供当前 We 计算；Buffer B 同时预取下一组 We+1。
03 · MXU + VPU 计算当前 Expert Wave Tokens 与 We 就绪后执行 FFN1 / FFN2；Act、scale 和 y_acc 留在 VPU / VMEM。
04 · ICI 结果就绪立即 Gather 一个 wave 完成便开始回传，不等待所有 experts；与后续 wave 的预取和计算重叠。
