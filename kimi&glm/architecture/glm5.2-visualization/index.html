Chapter 10 / Kimi K3 answers

K3 的回答：固定状态、按层重读、低维专家路径

第 9 页提出的三个 scaling 问题，在 K3 里分别落到 token、depth、channel 三条信息流；每一条都避免“规模变大就全量付费”。

Three problems → three mechanisms state · depth attention · latent experts
问题页问：历史、深层表示、模型容量扩大后，怎样不让每个 token 全量付费？ → K3 的共同回答是：先压缩，再按内容选择

跨 Token：

KDA 把长历史持续写进固定尺寸 state。主干按 3× KDA + 1× Gated MLA 交替：高频路径不再保存逐 token KV，周期性的全局注意力保留紧凑 latent KV。

t₁t₂…t
KDAKDAKDAGated MLA

跨 Depth：

Block AttnRes 把不同深度的表示变成可寻址 sources。当前层用 learned query w 生成权重 α，按内容重读 embedding、前序 blocks 与当前 partial sum。

跨 Channel：

Router 读取 full-width x；W↓ 只压缩送往专家的 payload。两条路径并行：routing scores 从 x 选 expert，latent z 再被 dispatch、计算与聚合；RMSNorm / SiTU-GLU 稳住数值，QB 对齐专家负载。

一一对应：逐 token KV → 固定状态·等权残差 → 按深度注意·full-width 选路 → latent payload

Chapter 11 / Kimi Delta Attention

KDA：固定状态如何遗忘、修正、写入和读取

每个 token 都更新同一个 dk×dv 状态。按实际计算顺序读：先对旧状态做 channel-wise 遗忘，再修正当前 key 方向，写入新的 value，最后由 query 读取。

KDA state update · one attention head state → forget → correct → write → read
① FORGET · Diag(αt)St−1 先缩放旧状态的每个 key channel：α 接近 1 多保留，接近 0 多遗忘。
② CORRECT · I − βtktkt⊤ 压低当前 key 方向上的旧关联，为同一方向的新内容腾出空间。
③ WRITE · + βtktvt⊤ 把新的 key → value 关联写入状态；βt 同时控制修正与写入强度。
④ READ · ot = St⊤qt query 从更新后的状态中读取输出，无需回看一条随 T 增长的状态列表。

Chapter 13 / Attention Residuals

AttnRes: 让当前层沿网络深度选择信息

第二个回答：把 residual 的固定等权累加改成 depth attention，让当前层按内容选择此前 block，避免单层贡献被持续稀释。

Standard Residual · Full AttnRes · Block AttnRes official architecture overview
(a) Standard Residuals每个子层输出以固定单位权重加入同一条 residual stream。
(b) Full AttnRes每层用 learned w 生成 α，对全部早期表示做 depth attention。
(c) Block AttnRes层内仍做普通 residual；只在 block representations 之间做 attention，把状态量从 O(Ld) 降到 O(Nd)。

Chapter 14 / Stable LatentMoE

LatentMoE 只压缩专家路径，省下带宽换更多专家

不是把整个模型变窄，也不是先压缩再 Router：Router 与 shared experts 仍读取完整 x[d]；只有 routed payload、专家计算和 All-to-All 进入更窄的 latent space ℓ。

Decision stays in d · specialist payload moves in ℓ bottleneck → route → two paths → stabilize → reinvest
为什么 Top-k 增大后，MoE 不再“便宜”？ 稀疏只控制 FLOPs；Serving 还要为权重读取和跨卡 token 搬运付费。
HBM weight bytes ∝ K · d · m 低 batch / 低延迟时，每个激活专家都要读取 d×m 级别的权重。
All-to-All bytes ∝ tokens · K · d 高吞吐 Expert Parallel 中，每条 routed payload 都带着完整 d 维 token。
ROUTERdecision · d 维 x[d] → Sigmoid(Wrx) → Top-k indices + weights Router 从完整表示做选择；W↓ 不在 Router 前面，压缩不会削弱选路所见的信息。
ROUTEDpayload · ℓ 维 x[d] → W↓ → z[ℓ] → dispatch → Ei → combine → RMSNorm → W↑ 真正跨卡发送并进入 routed experts 的是 z[ℓ]；专家权重和通信宽度都从 d 缩到 ℓ。
SHAREDcommon · d 维 x[d] → Σ Eshared(x) ───────────────┐ 公共变换保持 full width；它与 W↑ 后的 routed output 都回到 d 维，再相加得到 y[d]。
为什么叫 Stable RMSNorm在 W↑ 前固定 routed aggregate 的尺度 SiTU-GLU限制专家 FFN 的极端乘法激活 QB训练时按分位数更新选路 bias；不是一条新数据路径
routed width: d → ℓ 权重读取与 All-to-All payload 约按 ℓ/d 缩小；省下的成本可以换成更大的 expert pool 和更高 Top-k。

Chapter 15 / Native multimodality

Native Vision：联合训练，标准推理

MoonViT-V2 相比前代主要改变训练方式：视觉塔与 K3 从头共享单一 next-token loss。推理时仍由 ViT 理解图像，经 projector 转成视觉 embedding，再与文本 embedding 一起交给 K3。

训练创新 · 推理路径保持熟悉 单一目标 → 联合反传 → 从头训练 → 视觉 embedding 入模
前代 / 常见 VLM · 视觉塔先单独预训练，再做模态对齐 视觉编码器、projector 与语言模型通常分阶段训练。
MoonViT-V2 · 视觉塔与语言主干从头联合训练 同一个 next-token loss 贯穿视觉理解、特征投影和文本预测。
单一 NEXT-TOKEN LOSS共同优化目标 视觉 token 与文字一起作为上下文，模型仍然预测下一个文本 token 预测错误只形成一份 next-token loss；这份 loss 既约束最终的文本生成，也会反向塑造前面的视觉表示。
端到端联合训练全部参与更新 loss 的梯度同时更新 K3、MLP projector 和 MoonViT-V2 不是冻结 text backbone 后只训练 ViT 或 adapter；视觉塔和语言主干从预训练开始就在同一个任务中共同学习。
MoonViT-V2 从头训练不沿用 SigLIP 初始化 不先训练一套对比学习视觉编码器，再把它接到语言模型上 论文观察到从头联合训练的梯度更稳定；视觉表示也会直接围绕 OCR、文字和细粒度结构理解形成。
推理仍是标准 VLM 训练方式改变，但视觉输入进入语言模型的数据流没有改变。
图片 / 视频→ MoonViT-V2→ MLP projector→ 视觉 embedding
进入文本主干推理 视觉 embedding 被插入文本 embedding 序列，之后由同一个 K3 backbone 继续推理。
